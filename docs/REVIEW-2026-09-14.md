## Executive summary

Counts by severity: 2 Critical, 26 High, 44 Medium and 11 Low finding groups, one hypothesis-only entry, and 42 specification gap rows.

The three most important defects:

1. DS-01: applying headers, footers, watermarks or Bates numbers a second time, or removing them, deletes the page's original content.
   Executed in this session: after the second apply the body stream is gone and after removal the page keeps only an empty `q` stream.
2. DS-02: switching PDF.js editor mode clears the dirty flag and native dirty tracking while form or annotation-storage edits are pending, so closing loses them without a prompt.
3. DS-03: pdf-lib never garbage-collects, so every "delete" (pages, annotations, attachments, decoration and OCR layers) leaves the deleted objects in the saved file, and page extraction copies link-target pages as orphans.

Cross-cutting themes:

- Geometry: most placement code assumes MediaBox origin (0,0) and unrotated pages, so rotated or offset pages misplace notes, shapes, signatures, fields, links and crops.
- Concurrency: annotation property edits, autosave and dialog submits are not serialized, so overlapping mutations can overwrite each other or flood history.
- Encrypted sources: the native layer will overwrite an encrypted original with plaintext when the picker returns the same path, and protecting in place keeps writing plaintext recovery files.
- Dialogs: 18 hand-rolled modals lack Escape handling, programmatic labels and busy guards; Fill & Sign has no stylesheet at all.
- Tests: several tests contain zero assertions or assert on local copies of production logic; most mutation-dialog tests only check that a mock was called.
- Documentation: reopened phases still contain verbatim "complete" statements, retracted implementation descriptions remain, and `ARCHITECTURE.md` describes the Phase 1 state as current.
- Memory: idle is an ordinary 109 MB, but the first edit makes the whole file resident in the renderer, the revision history keeps up to 20 whole-file copies (1.4 GB measured for a 73 MB file), and autosave re-serializes and re-parses the whole document every ten seconds while dirty; the stack is not the cause and the fix is to let the native layer own the bytes (see the memory section).
- Reader parity: measured against Acrobat Reader rather than the specification, 17 day-one capabilities are missing, led by view rotation, read mode, go-to and back navigation, page labels, layers, attachments and signatures panels, stamps, callouts, text-correction markup, measurement tools, print options and confirmed external links (see the parity table).

## Data safety and persistence

### DS-01 Critical: re-applying or removing decorations deletes original page content

Location: `src/services/document-commands.ts:1126-1127`, `:1236-1246` (decorations), `:1351-1352`, `:1362-1372` (Bates), `:1047-1090` (`removeDocumentDecorations`), `:1098` (pre-strip on apply).
The code records `beforeSize` of the page `/Contents` array before the first `drawText` call and later tags every stream in `beforeSize..afterSize` with `NavPDF_Decoration`.
pdf-lib's first draw normalizes a single-stream page into `[q, original, Q]` and appends the new stream, so the window covers the original stream and the shared `q`/`Q` streams.
Executed: a one-stream page became `q | original | Q | footer` after apply one, `q | q | Q | footer` after apply two, and `q` alone after removal.
Impact: changing a footer or clicking Remove decorations blanks every targeted page; only in-memory undo can recover.
Existing tests use `createBlankDocument`, which has no content, so they cannot catch this.
Fix: build the decoration stream explicitly with `doc.context.stream(...)` and `page.node.addContentStream(ref)`, tag only that ref, and add a regression on a page with existing content.
Plan: T1.1.

### DS-02 Critical: dirty state cleared by editor mode switch while storage edits are pending

Location: `src/features/viewer/controller.ts:147-175`, `:221-233`.
The `editingstateschanged` handler sets `dirty: false` and calls `markDirty(false)` whenever the PDF.js command manager has nothing to undo or redo and history is at the saved revision.
PDF.js dispatches that event from `setEditingState` on every editor mode change, and form-field or storage edits recorded by `onSetModified` never enter that check.
Source: type into a form field, click Highlight, close the document; no prompt, and native recovery bookkeeping says clean.
Fix: derive dirty from `history.isAtSavedRevision() && !storageModified`, set `storageModified` in `onSetModified`, reset it on attach and `markSaved`, and use the event only for undo/redo/selection flags.
Plan: T1.2.

### DS-03 High: deleted objects remain in saved files; extraction copies orphan pages

Location: `src/services/document-commands.ts:374-392` (`deletePages`), `:344-354` (`deleteAnnotation`), `:1699-1753` (`deleteEmbeddedAttachment`), `:1047-1090`, `:1818-1861` (layer removal), `:437`, `:517`, `:547` (`copyPages` in extract, merge and split).
pdf-lib serializes every indirect object, so removed page dictionaries, annotation dictionaries and embedded file streams stay in the output.
Executed: two `/Type /Page` dictionaries survive a one-page delete; an embedded file survives its own deletion; extracting page 1 of 2 with a link to page 2 yields one tree page but two page objects.
Impact: "share only page 1" leaks page 2 content; deleted comments and attachments remain recoverable, contradicting the removal invariant.
Fix: add a native prune step through lopdf `prune_objects` plus renumbering for delete operations when native is available, strip or remap link destinations that point outside a selection before `copyPages`, and warn in browser preview.
Plan: T1.4.

### DS-04 High: unlock then save can overwrite the encrypted original with plaintext

Location: `src-tauri/src/commands/engine.rs:321-340`, `src-tauri/src/commands/mod.rs:359-385`, `src-tauri/src/filesystem/mod.rs:102`.
`engine_unlock` stages plaintext and sets `force_save_as`; the save path only forces the picker, suggests the current file name, and accepts `target == source`.
The frontend routes this through the Protect dialog first (`src/app/useDocumentSession.ts:181-187`), so the user has made an explicit "save unprotected copy" choice, which is why this is High rather than Critical.
Source: choosing Replace on the suggested name replaces the encrypted contract with an unencrypted file, and `validate_pdf` even rejects encrypted output so the result is always plaintext.
Fix: refuse `target == canonical(source)` when `sensitive` is set or the snapshot has `/Encrypt`, suggest a `-unlocked` name, and add a Rust test using `protect::protect` output.
Plan: T1.3.

### DS-05 High: protecting in place leaves plaintext recovery and working copies

Location: `src-tauri/src/commands/engine.rs:285-305`, `src-tauri/src/commands/mod.rs:622-643`.
`engine_save_protected` allows replacing the source and only updates `source` and `force_save_as`; `sensitive` stays false.
Source: autosave keeps writing unencrypted `recovery.pdf` for a document whose file is now encrypted, working revision files stay plaintext, and the next Save uses the encrypted file's hash as the check and writes plaintext back.
Fix: on `replaced_source`, set `sensitive`, delete the recovery slot, drop the working file, and refuse plain overwrite of the now-encrypted target.
Plan: T1.3.

### DS-06 High: session flags from attach are wiped by the post-load reset

Location: `src/app/useDocumentSession.ts:88`, `:109-115`; `src/stores/workspace.ts:63-64`; `src/features/viewer/controller.ts:260-272`, `:290`, `:302`.
`controller.attach` sets `hasDigitalSignature`, `formNotice` and `comments`, then `load` calls `reset()`, which clears all three and carries over only `bookmarks`.
Source: certificate-signed PDFs never show the redaction or Fill & Sign signature warnings until some later mutation re-attaches; `formNotice` has no consumer anywhere, so XFA and JavaScript notices are dead state; the Comments tab is empty after replacing a document.
Fix: snapshot those fields before `reset()` and re-apply, render `formNotice`, and add a regression asserting the flags survive `session.load`.
Plan: T1.8.

### DS-07 High: autosave takes `busy` and `inert` every ten seconds and clobbers other operations

Location: `src/app/useDocumentSession.ts:322-337`; `src/app/App.tsx:68-72`, `:201`.
Each tick sets `busy: true` (making the workspace inert and swallowing keydown) for the duration of `saveDocument()` and then unconditionally sets `busy: false, status: "Unsaved changes"`.
The tick checks the session lock but not `state.busy`, and page operations set `busy` without the lock.
Source: typing in a free-text annotation is interrupted every ten seconds on large files, and a tick during a page mutation re-enables the UI mid-operation and overwrites its status.
Fix: make recovery writes passive (no `busy`), skip the tick when `busy` is already set, restore the prior status, and consider a busy owner token instead of a boolean.
Plan: T1.8.

### DS-08 Medium: opening another document silently deletes a pending recovery copy

### DS-09 Medium: single recovery slot and handle map shared by all documents natively

## Native layer (Rust)

### NAT-01 High: "Remove hidden content" makes layer-hidden annotations visible

Location: `src-tauri/src/engine/redact.rs:818-885`, `:1080-1091`.
The catalog `/OCProperties` is deleted but annotation `/OC` entries are never evaluated, so annotations hidden by a layer become visible in the sanitized output.
Fix: before deleting `/OCProperties`, remove annotations whose `/OC` or OCMD `/OCGs` resolve into the hidden groups and count them in the report.
Plan: T1.5.

### NAT-02 High: one unreadable signature asset hides the whole library

Location: `src-tauri/src/signatures/mod.rs:61-67`, `:179-182`, `:259-268`.
`list()` propagates the first `read_asset` error; a legacy v1 asset sealed under a different `USER` value fails its tag and all valid v2 assets disappear with it.
A legacy asset whose upgrade rewrite fails on a read-only directory also fails the list instead of returning the decrypted asset.
Fix: skip and report unreadable entries through a `warnings` field and a log record.
Plan: T1.7.

### NAT-03 High: the redaction term audit materializes every decompressed stream twice

Location: `src-tauri/src/engine/redact.rs:1243-1259`; `src-tauri/src/engine/mod.rs:22`.
All streams (each up to 512 MB) are pushed into one vector and then lower-cased into a second copy.
Impact: a 300-page scanned PDF can need several GB of resident memory during Apply.
Fix: check all terms against each decompressed stream in turn and drop it before the next.
Plan: T2.7.

### NAT-04 Medium: compression keeps color-key `/Mask` arrays on resampled or JPEG images

Location: `src-tauri/src/engine/images.rs:37-47`, `:271-280`; `src-tauri/src/engine/compress.rs:400-409`, `:416-568`.
Only stream masks are rejected; averaged or quantized samples no longer match the key ranges, so transparent backgrounds become opaque and the fidelity fingerprint counts placements, not pixels.
Fix: refuse re-encoding of color-key masked images, or strip the mask only for lossless unresampled output.
Plan: T2.7.

### NAT-05 Medium: the redaction audit is not independent of the rewrite

Location: `src-tauri/src/engine/redact.rs:1113-1209`; `src-tauri/src/engine/content.rs:436-447`, `:469-483`; `src-tauri/src/engine/fonts.rs:134`.
The audit reuses the same scanner, font metrics and image decoder; when a font is non-segmentable the advance is estimated and fed into the text matrix, so later glyphs in the same text object are misplaced consistently in both passes.
Hypothesis on frequency; the mechanism is confirmed.
Fix: add a second check through lopdf `extract_text` per page, and treat any non-segmentable run within a region's font size as a rejection rather than an estimate.
Plan: T2.7.

### NAT-06 Medium: synchronous commands stall the main thread

Location: `src-tauri/src/commands/mod.rs:482-513`, `:523-539`, `:705-732`.
`get_revision` takes a lock that `commit_revision` holds across a full lopdf parse and a synced temp write; signature commands do Keychain I/O and AES work synchronously.
Fix: make them `async` with `spawn_blocking`, and shrink the `commit_revision` critical section to compare-and-publish.
Plan: T3.7.

### NAT-07 Medium: OCR page images cross IPC as JSON number arrays

Location: `src/services/native.ts:241-252`; `src-tauri/src/commands/mod.rs:890-897`.
A 32 MB PNG becomes a 100 MB JSON string; every other byte payload already uses the raw invoke body.
Fix: accept `Request<'_>` with a raw body and pass options in headers.
Plan: T3.7.

### NAT-08 Medium: `validate_pdf` messages talk about saving when printing or committing revisions

Location: `src-tauri/src/filesystem/mod.rs:101-106`; `src-tauri/src/commands/mod.rs:489`, `:853`.
Fix: return a neutral error variant and let callers map the message.

### NAT-09 Medium: permissions-only protection is impossible

Location: `src-tauri/src/engine/protect.rs:92`, `:184-186`.
An empty user password is rejected, so "anyone can open, nobody can copy or print" cannot be produced; encrypted input cannot be re-encrypted or have its owner password changed.

### NAT-10 Medium: certificate signing lacks timestamps, appearance and trust evaluation

## Viewer, annotations and document commands

### VIEW-01 High: property edits race each other and flood history

Location: `src/features/annotations/Properties.tsx:42-57`, `:59-93`, `:125-136`; `src/features/viewer/controller.ts:331-416`, `:744-767`.
Every `onChange` tick of the color picker, sliders and note textarea calls `updateSelectedAnnotation`; `replaceWithBytes` is not re-entrant and `applyAnnotationEdit` never checks `busy`.
Source: overlapping calls save from the same base and the later one wins; each tick is a full revision so the 20-entry history evicts real edits; fast typing loses characters because the textarea is controlled by the reloaded value.

### VIEW-03 High: attachment listing, extract and delete fail silently when `/Names` is indirect

### VIEW-04 Medium: clamps assume MediaBox origin (0,0); sticky-note default ignores rotation

## Memory, performance and security posture

The owner reports that the app takes a large amount of memory and slows the machine.
This section records what was measured on this machine (Apple silicon, macOS 25.6) at `4f667c1`, what the code does with document bytes, and what follows for the language question.

### Measurements

Idle release app, home screen, no document, measured with `footprint` over the app process and its three WebKit helper processes:

| Process | Physical footprint | Resident set |
| --- | --- | --- |
| `navpdf` (Rust, Tauri) | 27 MB | 103 MB |
| WebKit WebContent (React UI, PDF.js, worker) | 62 MB | 90 MB |
| WebKit GPU | 14 MB | 37 MB |
| WebKit Networking | 6 MB | 16 MB |
| Total | 109 MB | 246 MB |

That idle total is ordinary for a WKWebView application and is not where the reported pressure comes from.
The `npm run desktop` development build is materially heavier (Vite dev server, unminified bundles, source maps, devtools); if the report was made against that build, the release bundle should be measured instead.

The GUI could not be driven to open a document from this session: macOS refused synthetic keystrokes because the terminal lacks Accessibility permission, the same blocker recorded in PR-2.
The JavaScript side was therefore measured with a Node probe (`pdfjs-dist` 6.3.289, the same phases the app runs) against two generated image-heavy files; the Rust side through the `engine_cli` example.
Numbers are deltas from the probe baseline; "ext+ab" is external plus array-buffer memory, which is where PDF bytes live.

### Where the memory goes (confirmed in code)

MEM-01 High: the first edit turns a streamed document into a fully resident one.
`src/features/viewer/controller.ts:331-372`: every mutation copies the candidate twice (`candidateBytes`, `historyBytes`), serializes the previous revision with `saveDocument()`, transfers one copy to the worker through `loadPdfFromBytes` (`src/services/pdf.ts:82-85`, `data:` mode) and commits another copy over IPC to the native working file.
From then on PDF.js holds the whole file in the worker instead of fetching 64 KB ranges, so a 363 MB scan costs at least 363 MB in the WebContent process plus the transient copies above.
Plan: T8.1.

MEM-02 High: the revision history keeps up to 20 whole-file copies in the renderer.
`src/services/revision-history.ts:30`, `:136-139`, `:150` and `copyRevision` on every read: bound by count, not bytes, and copied on adopt, push and read.
Measured: 1.4 GB resident for a 73 MB file at the limit.
The native layer already owns a working revision file per commit (`src-tauri/src/commands/mod.rs:482-513`), so these copies duplicate data that is on disk.
Plan: T8.1.

MEM-03 High: autosave re-serializes and re-validates the whole document every ten seconds while dirty.
`src/app/useDocumentSession.ts:310-338` calls `saveDocument()` (two file sizes of transient memory and worker CPU), copies the bytes over IPC, and `write_recovery` (`src-tauri/src/commands/mod.rs:622-655`) hashes the previous recovery file and runs `validate_pdf`, a full lopdf parse (2.2 times the file size), before an atomic write.
Nothing checks whether anything changed since the previous recovery write, so an idle dirty document repeats this indefinitely.
For a 363 MB scan that is roughly 1.5 GB of allocation churn and several seconds of CPU every ten seconds, which matches "my system slows down".
Plan: T8.2.

MEM-04 Medium: PDF.js never evicts fetched byte ranges.
`ChunkedStream` in `pdf.worker.mjs` keeps every loaded chunk for the life of the document, and `disableAutoFetch` only stops speculative reads.
Search indexing (`controller.ts:950-980` through `PDFFindController`) touches every page's content stream, so a scanned document ends up mostly resident even in range mode (+374 MB for the 363 MB file); `cleanup()` does not release it.
Plan: T8.3.

MEM-05 Medium: canvas budget at high zoom.
`controller.ts:89` allows 8,000,000 pixels per canvas (32 MB) and PDF.js keeps a 10-page view buffer by default (`DEFAULT_CACHE_SIZE = 10` in `pdf_viewer.mjs`), so 500 percent zoom on a Retina display can hold about 320 MB of canvases plus the thumbnail canvases.
Plan: T8.4.

MEM-06 Medium: native budgets are absolute, not relative to the machine.
`src-tauri/src/commands/engine.rs:18-21` allows 8 staged buffers up to 1.25 GB; `MAX_FILE_BYTES` is 1 GB (`filesystem/mod.rs:9`); every engine operation loads through lopdf at about 2.2 times the file size and compression peaks at 4 to 5.5 times.
A 1 GB input is therefore permitted although protecting or compressing it needs more than 4 GB of native memory on top of the renderer.
Plan: T8.5.

MEM-07 Medium: repeated whole-document passes per mutation.
Every annotation edit reads the annotations of every page twice (VIEW-09), commits the full bytes natively (a lopdf parse), and property sliders fire this per tick (VIEW-01).
Plan: T2.1, T8.1.

MEM-08 Low: startup payload.
The production `App` chunk is 1.40 MB minified plus a 1.32 MB PDF.js worker; the idle WebContent footprint of 62 MB reflects this.
Code splitting (T6.3) trims first paint; it does not change document memory.

### What the language question comes down to

The measurements do not indict Rust, TypeScript or WebKit.
Idle cost is 109 MB across four processes, which any WKWebView or Electron application pays and a native AppKit application would roughly halve.
The growth comes from three design choices in this codebase: holding whole-document byte arrays in the renderer after the first edit (MEM-01, MEM-02), re-serializing the whole document on a timer (MEM-03), and letting the PDF.js worker retain every fetched range (MEM-04).
All three are fixable inside the current stack because the native layer already owns an immutable snapshot and a working revision file per commit; the renderer only needs to stop keeping its own copies.

Options considered:

| Option | Memory outcome | Cost | Recommendation |
| --- | --- | --- | --- |
| Keep Tauri, Rust, React, PDF.js; move byte ownership to Rust and reload revisions through the range transport (Tranche 8) | Renderer holds only fetched ranges plus canvases; history lives on disk; autosave becomes a native file copy | Weeks, no rewrite, all existing tests and acceptance stay valid | Do this first |
| Swift and AppKit with PDFKit (macOS only) | Leanest possible; PDFKit renders from the file with its own cache | Full rewrite; loses Windows and Linux path, PDF.js annotation editors, the redaction, signing and OCR integration work; PDFKit annotation fidelity differs from Acrobat | Only if macOS-only and a rewrite are acceptable |
| Rust with PDFium rendering instead of PDF.js | Bounded native rendering, no worker copies | New rendering, text layer, selection, form and annotation UI; PDFium packaging and license notices; ADR 0006 declined it | Revisit only if Tranche 8 fails to meet the budget |
| Electron or another Chromium shell | Worse: Chromium baseline is higher than WKWebView | None | No |

The recommendation is to keep the stack and execute Tranche 8, then re-measure with the same probes and, once Accessibility permission is granted to the terminal, with the release app itself (the driver script for that is `scripts/memory-drive.sh` in T8.6).
Target budget after Tranche 8: idle under 120 MB footprint, a 363 MB scanned document open under 300 MB footprint across all processes, and no allocation proportional to file size on a timer.

### Security posture

Confirmed strengths: strict production CSP with no remote origins (`src-tauri/tauri.conf.json:26`); no IPC command accepts a renderer-supplied filesystem path; capabilities limited to `core:default`; navigation restricted to the app origin; PDF JavaScript never executed; encrypted input read-only until an explicit unlock; recovery never written for sensitive sessions; signature assets under a random AES-256-GCM key in the Keychain with per-write nonces; passwords excluded from logs; bounded range reads; redaction output fully rewritten and pruned.

Gaps, in priority order (defects already listed elsewhere are referenced by id):

- DS-04, DS-05: plaintext overwrite of encrypted sources and plaintext recovery after protecting in place.
- NAT-01: layer-hidden annotations survive "remove hidden content".
- The bundle is ad-hoc signed with no entitlements: `codesign -dv` reports `flags=0x20002(adhoc,linker-signed)`; there is no hardened runtime, no App Sandbox, no notarization, and Gatekeeper will block the DMG on other machines.
  App Sandbox is compatible with this design because every file comes from the user's picker; recents would need security-scoped bookmarks.
  Plan: T8.7 and the open Phase 9 gate.
- `isEvalSupported` is not set for PDF.js (`src/services/pdf.ts:66-85`); production CSP already forbids `eval`, but the flag should be explicit so the dev CSP (`'unsafe-eval'`) does not create a behavior difference.
  Plan: T8.7.
- NAT-11: passwords cross IPC as JSON arguments and are not zeroized.
- DS-13: symlink destinations are replaced rather than followed.
- NAT-03: the redaction audit's memory use is a denial-of-service vector on large scans.
- DS-03: deleted objects remain recoverable in saved files.
- External links are disabled rather than confirmed (Task 7.8 must keep the scheme allow list when it adds the prompt).
