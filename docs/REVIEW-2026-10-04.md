# October 4 feature and reliability review

Reviewed base: `4902cfc` on `origin/main`.
The working tree was clean at the start of the review.
This report checks current source against the product specification and active delivery tracker, with focused native workflows and the required automated gates.
It is not an exhaustive native acceptance run for every tool.

## Confirmed corrections

### Import failures hidden behind the dialog

In the packaged native app, Create > Import / Combine Files > `reader-5.pdf` > range `99` > Combine & Open left the dialog unchanged while the error appeared behind its blurred backdrop.
The same error routing affected PDF parsing, image import and blank-document creation failures.
Create PDF now owns an accessible alert inside its modal and clears it when an operation is retried.
The queued files, ranges and image adjustments remain available after failure.
Regression tests use real synthetic PDFs to exercise invalid ranges, damaged input, removal and successful retry, and verify the resulting page dimensions.
A browser-only TIFF rejection test covers mixed successful/failed input selection without claiming native TIFF decoding evidence.

### Empty comparison filter

Comparing a synthetic PDF with its saved copy and enabling Only changes left an enabled page selector with no options and no explanation.
The dialog now reports that no changed pages were detected, explains how to restore matching pages, and disables the empty selector.
Comparison progress distinguishes text reading from rendering.
The regression checks both the empty state and restoration of matching-page previews.

### Unresolved native observation

The initial baseline process stayed on Reading original page 1 while comparing a two-page synthetic document with its saved copy.
A fresh launch completed the same comparison, and a second create/save/compare journey also completed.
The cause was not isolated and this PR does not claim to fix that stall.
Retest a long-lived native session, including sleep/wake and repeated comparisons, before closing this observation.

## Feature assessment

| Area | Current source | Remaining scope or evidence |
| --- | --- | --- |
| Reader, navigation and search | PDF.js viewing, page labels, thumbnails, bookmarks, search, history, layers, speech and auto-scroll are implemented in `src/features/viewer/` and `src/features/search/`. | Full native keyboard, assistive-technology and large-document performance acceptance is broader than this review. |
| Page tools and composition | Create, range-based import, merge, rotate, reorder, crop, extract and split are implemented in `src/features/pages/` and `src/services/document-commands.ts`. | Preserve the explicit limitations for signed, XFA and scripted form composition; cropping does not securely remove hidden content. |
| Image preparation | Margin trim, manual crop, straightening, background cleanup and batch processing exist; HEIC/TIFF decoding uses macOS ImageIO. | Automatic document-edge detection, perspective correction and scanner acquisition are absent. |
| Markup, forms and signatures | Annotation tools, form filling/creation, existing-field values/flags, local signature appearances and certificate signing have source and regression coverage. | Existing-field geometry editing is still absent from FormManager; appearances and certificate signatures remain separate capabilities. |
| Existing content editing | `src-tauri/src/engine/edit.rs` supports bounded text-run and image edits. | Paragraph reflow is absent; CID/Type 3 fonts and unavailable subset glyphs are refused. |
| OCR | Local macOS recognition, review before apply and correction of saved app-owned OCR are implemented. | Other platforms lack a real recognition engine; arbitrary existing OCR layers are not editable through the app-owned review format. |
| Compression and comparison | Measured presets, target-size attempts and previews are implemented; comparison aligns exact matching pages and compares text and reduced-resolution renders. | A target size is not guaranteed; reduced-resolution comparison does not certify identity. |
| Export and conversion | Text, images, DOCX, XLSX, RTF and editable-text or page-picture PPTX exports are implemented in `src/features/convert/`. | Office import and general layout-preserving editable conversion are absent. |
| Protection and redaction | Native encryption, unlock and audited redaction have dedicated implementations and adversarial suites. | This review does not renew all independent removal, password-reopen or Acrobat compatibility evidence. |
| Distribution | Local macOS app/DMG packaging is configured. | Signing, notarization, clean-account installation, physical printing and Windows/Linux native acceptance remain open. |

## Prioritized follow-up

1. Complete the remaining macOS distribution and clean-account acceptance gates before making release-ready claims.
2. Extend native saved-output checks for rotated/cropped forms, mixed-size documents, OCR correction and combined workflows, including reader-specific limitations already recorded in the tracker.
3. Add existing-form-field move/resize controls with saved-widget geometry tests and independent-reader acceptance.
4. Decide whether Office import and higher-fidelity editable conversion justify a separate local engine trial and licensing/packaging decision.
5. Evaluate document-edge/perspective correction and scanner acquisition as separate additions with a representative scan corpus.

Model-based translation/generation, cloud collaboration and remote signing remain deferred or declined by ADR 0008 and ADR 0010.
They are intentional scope decisions, not hidden completed features or regressions to fix in this PR.
Detailed current evidence and limitations are recorded in [VERIFICATION.md](VERIFICATION.md).
