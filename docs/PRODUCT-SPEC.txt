### One change I would make when you actually build it

I would **not tell the agent to immediately attack existing-text editing**. Get this sequence working first:

**Viewer → page manipulation → annotations → add text/images → forms/signatures → OCR → existing-text editing → redaction.**

And importantly, I would **not use Java for this project**, despite Java being a good fit for most of your backend work. For this particular application, **React + Tauri + Rust + PDF.js/native PDF libraries** gives us a much better path to a polished native-feeling PDF editor.

### An even better way to use this prompt

Don't dump the prompt into the coding agent and tell it, **“finish everything.”** Give it the master prompt, but instruct it to execute only **Phase 1** first. Once you have a real PDF viewer running on your Mac, move through the phases one at a time.

That prevents the typical AI-generated-app problem where you end up with 40 buttons and only 12 of them actually work.

For **our first milestone**, I would consider NavPDF successful when you can open a 500-page PDF, scroll smoothly, search it, use thumbnails, zoom, highlight something, save it, reopen the resulting file in Apple's Preview, and still see the highlight. After that foundation is rock solid, the Acrobat-like editing features become much safer to add.
